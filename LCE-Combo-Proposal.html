LCE Combo Strategy

v1.0 Draft Prepared July 2026  ·  W James Miles Trading Profits Pro
Overview

One strategy. Multiple rule sets. Single install.

The LCE Combo Strategy consolidates the LCE Original Manual / Opening Short rule set and the MES_Aplus rule set into a single compiled NinjaTrader strategy. End users install one package, see one strategy, and control which rules are active through a standard properties panel — no source code required.

Internally, the two rule sets remain structurally independent so they can be developed, tested, and versioned separately without one set of changes affecting the other.

Architecture

Three source files. One compiled output.

NinjaTrader compiles all strategy files together, which allows a single strategy class to be split across multiple files using C# partial classes. Each rule set lives in its own file, and a thin coordinator file ties them together. All three compile into one DLL.

LceComboStrategy.cs
Coordinator. Strategy class declaration, all parameters, OnBarUpdate dispatcher, session management, spread fetch, Discord webhook, position coordination between rule sets.
LceComboStrategy_LCE.cs
Partial class. All LCE indicators, EMA cloud state, level management, Original Manual entry logic, Opening Short entry logic, LCE exit management.
LceComboStrategy_MES_Aplus.cs
Partial class. All MES_Aplus indicators, zone management, EMA logic, TICK and ARM entry logic, MES_Aplus break-even and exit management.

Why partial classes? Each rule set file is self-contained — its own indicators, state variables, and entry/exit logic. A developer working on MES_Aplus edits only LceComboStrategy_MES_Aplus.cs. Changes to that file cannot affect LCE code in a different file, and the diff is clean and reviewable in isolation.

Position Coordination

Controlling how rule sets interact.

MES_Aplus uses an arming technique: a setup condition is met and the strategy arms before an actual entry order is placed. The Allow Concurrent Positions parameter controls whether LCE treats MES_Aplus's armed state as an occupied slot. When set to False, LCE is blocked the moment MES_Aplus arms — not just when it enters. This prevents LCE from opening a position that would compete with a MES_Aplus entry that is already committed but not yet filled.

The reverse gate (MES_Aplus blocked by an open LCE position) continues to use actual position state, since LCE has no arming step.

Setting Scenario Behavior
False (default) LCE is in a position; MES_Aplus signal fires MES_Aplus signal is skipped. One active trade at a time.
False MES_Aplus is armed; LCE signal fires LCE signal is skipped. Armed state is treated as occupied — LCE waits until MES_Aplus is neither armed nor in a position.
True MES_Aplus is armed; LCE signal fires LCE enters independently. Armed state does not block LCE.
True LCE is in a position; MES_Aplus signal fires MES_Aplus enters independently. Both positions run with their own stops and targets.
True Both signals fire in the same bar Both enter. Session force-close at 15:55 ET closes all open positions.
Development Workflow

How each rule set is updated independently.

Because each rule set lives in its own file, updating one does not touch the other. The workflow for any change is the same regardless of which rule set is being modified.

1
Make the change in the rule set's own file
LCE changes go in LceComboStrategy_LCE.cs. MES_Aplus changes go in LceComboStrategy_MES_Aplus.cs. The coordinator file is only touched when adding a new shared parameter or changing coordination logic.
2
Test in isolation by disabling the other rule set
Set EnableLCE=True, EnableMES_Aplus=False to backtest LCE changes alone. Set EnableLCE=False, EnableMES_Aplus=True to backtest MES_Aplus changes alone. Results should match the prior version exactly except for the intended change.
3
Test combined behavior with both enabled
Run with both rule sets active to verify coordination logic behaves correctly — especially at session boundaries, daily loss limits, and concurrent signal scenarios.
4
Bump the version and update the changelog
The combo strategy has its own version number (e.g. v1.0.0, v1.1.0) tracked independently from any internal rule set versioning. Each release notes which rule set changed and why.
5
Compile and package
The three source files compile to a single DLL. The installer packages the DLL and drops it into the NinjaTrader AddOns folder. No source code is distributed to end users.

Distribution

What gets shipped and how.

The end-user install package contains only the compiled DLL and any supporting data files (level CSV, spread CSV). No NinjaScript source is included. The installer registers the strategy with NinjaTrader so it appears immediately in the strategy selector without manual import.

Package contentsPurpose
MES_APlusV3.dllCompiled strategy — one file, both rule sets

User-visible strategy name: The strategy class can be given a clean display name (e.g. "MES_APlusV3") that differs from the class name, so the end user never sees internal naming conventions.
